## A. 核心方法 · 动态图 / 时序图（流形几何视角）

### 1. Geodesics of Dynamic Graphs for Regime Change Detection
- 链接：https://arxiv.org/abs/2606.07151
- 作者：William Cappelletti, Étienne Voutaz, Pascal Frossard（EPFL，LTS4 信号处理实验室，据 Frossard 背景推断）
- submit 日期：2026-06-05
- **TL;DR**：把动态图的"演化轨迹"建成图空间里沿测地线（geodesic）的运动，于是"状态切换"不再是突变型 change point，而是轨迹的显著漂移（换轨或变速）——首个在图空间里建模"渐变型 regime 之间切换"的工作。
- **解决什么问题 / 为什么重要**：传统动态网络变点检测假设系统在"平稳态之间突变"，与社交网络、物理系统等"持续演化"的现实不符。这正中你方向 A 的"temporal graph / dynamic graph"，而且方法论很对味——它把时序图的连续动力学纳入几何框架，而非把每个时刻当成独立快照，思路可迁移到 CTDG / 时空 GNN 的"漂移检测/概念漂移"问题。
- **核心方法**：把 regime 定义为"动力学一致的时段"，并刻画为图空间中两端点之间估计测地线上的轨迹；用图回归测量观测图序列相对该测地线的累积偏离距离，再接变点检测算法识别"换轨"或"变速"两类 regime change。
- **主要结果**：在含变轨迹、变速度的合成动态网络上优于 SOTA 变点检测；在 COVID-19 期间真实人口流动数据上，其"规则演化"假设给出的变点比基线更贴合真实外部事件（政策/疫情节点）。
- **值得追问 / 局限**：① "图空间 + 测地线"依赖所选图度量/嵌入，几何选择对结果的敏感性、以及在大规模/高频时序图上的可扩展性需看；② regime 假设为"分段测地线"，对真正高度非平稳、无明显轨迹结构的网络是否退化为普通变点检测，缺少压力测试。

## A×B 横切 · 不规则纵向时序 + 脑影像（神经退行）

### 2. Transition-Based Digital Twin Modelling for Alzheimer's Disease under Sparse Longitudinal Data
- 链接：https://arxiv.org/abs/2606.09671
- 作者（前几位）：Yinyu Huang, Yilin Zhang, Sofia Michopoulou, Christopher Kipps, Rahman Attar（英国机构，含临床神经科背景，据作者公开信息推断）
- submit 日期：2026-06-08
- **TL;DR**：用"相邻随访之间的转移建模"而非"整段序列建模"做阿尔茨海默病的个体化数字孪生预测，在稀疏不规则随访下反而更准、更省数据。
- **解决什么问题 / 为什么重要**：AD 进展高度异质，且观测是典型的**稀疏、不规则纵向数据**——这正是你方向 A"irregularly-sampled / asynchronous time series"在 B（neuroimaging time series）上的落点。文中给出一个有价值的实证发现：在 ADNI 这种稀疏不规则场景，"局部转移建模"比"序列建模"更数据高效，对你思考不规则时序该用 ODE/序列模型还是转移模型有直接参考。
- **核心方法**：个体化数字孪生框架，融合"临床转移建模"与"跨随访时间依赖建模"两类策略；输入 ADNI 的认知评估、临床变量与 MRI 衍生表型，预测认知评分与诊断类别，同时量化预测不确定性、支持 patient-specific 的 what-if 轨迹推演。
- **主要结果**：在 leak-free 的 subject-level 划分上，评分预测与诊断分类均表现良好；关键对比是"相邻随访转移建模 > 序列建模分支"的预测精度，提示局部转移更数据高效，而序列模型在不确定性感知的轨迹预测上仍有价值。
- **值得追问 / 局限**：① "转移建模优于序列建模"很可能与 ADNI 随访极稀疏强相关，随访更密时结论是否反转、临界采样密度在哪未讨论；② MRI 衍生表型只是标量特征输入，未触及脑网络/时空结构本身——对想做脑功能时序结构建模（含 fNIRS）的迁移价值有限。

## B. 监控告警 · 根因分析 / AIOps（生产级三连）

### 3. Graphical Causal Reasoning for Root Cause Analysis in Cloud Networks
- 链接：https://arxiv.org/abs/2606.13532
- 作者：Fabien Chraim, Dominik Janzing, John Evans（含 Janzing，背景指向 Amazon AWS 因果团队）
- submit 日期：2026-06-11（今日批次中真正"新"的高相关文）
- **TL;DR**：用基于图的因果发现做云网络故障 RCA——从二值时间序列上用双变量 Granger + 条件独立检验建因果图，再用"随时延变化的边条件概率"在图上做时间感知、可解释的根因打分。
- **解决什么问题 / 为什么重要**：与昨日（06-13）收录的同组 NetCause（2606.13543，反事实式 RCA）是姊妹工作但方法不同——这篇走"因果图发现 + 概率传播打分"路线，直接命中你方向 B 的"root cause analysis / AIOps"，且 spatiotemporal grouping + automation ontology 的降维思路有方法论价值。
- **核心方法**：先用 spatiotemporal grouping 策略 + automation ontology 给问题降维；在二值时序上用双变量 Granger 因果与条件独立检验构因果图；推理阶段给每条边赋"随时延变化的条件概率"，通过因果图遍历得到时间感知、可解释的根因评分。
- **主要结果**：在某头部云厂商 35 起生产标注事件上，正确召回根因 85.7%、精确匹配 74.3%；线上系统已用于 800+ 真实事件，获网络工程师正面反馈。
- **值得追问 / 局限**：① 评测仅 35 起标注事件，规模偏小；"800+ 线上事件"只是定性反馈、无量化指标，真实精度未知；② 二值化时序 + Granger/条件独立的因果图对采样粒度、时延选择高度敏感，因果发现的稳健性是这类方法最该被质疑处。

### 4. Anomaly Detection and Root Cause Analysis for Microservice Systems
- 链接：https://arxiv.org/abs/2606.09942
- 作者：Luan Pham（博士学位论文，澳洲机构，据作者背景推断）
- submit 日期：2026-06-08
- **TL;DR**：一篇系统性博士论文——把"异常检测"与"RCA"端到端联合做，覆盖 metric/event/多模态三类数据，并配套交付 RCAEval 基准与对因果推断式 RCA 的系统性评测。
- **解决什么问题 / 为什么重要**：明确点出当前 AIOps RCA 的五大通病（检测与 RCA 分离、event 数据被忽视、依赖给定调用图、缺标准数据集/评测、因果推断式 RCA 的有效性存疑），对你方向 B 是一份很好的"领域地图 + 工具箱"。三项方法（BARO/EventADL/TORAI）+ 基准（RCAEval）齐备，可直接拿来当 baseline 与数据源。
- **核心方法**：BARO——metric 数据的端到端异常检测+RCA；EventADL——面向 API 调用/配置变更等 event 数据；TORAI——无需服务调用图的多模态 RCA；外加 RCAEval 综合基准与对现有（尤其因果推断式）RCA 方法的系统评测。
- **主要结果**：在真实微服务系统上验证三套方法的有效性与稳健性；交付可复现基准与基线，并给出"因果式 RCA 在效率/稳健性上的边界"的实证洞察。
- **值得追问 / 局限**：① 论文体量大、跨多套方法与数据，单项方法相对最新 SOTA 的领先幅度需到对应单篇核对；② "无需调用图的多模态 RCA"很有吸引力，但其在缺乏拓扑先验时的归因稳定性仍是开放问题。

### 5. Auditable Graph-Guided Root Cause Analysis for Kubernetes Incidents
- 链接：https://arxiv.org/abs/2606.08590
- 作者：Anastasiia Kuvshinova, Seungmin Jin
- submit 日期：2026-06-07
- **TL;DR**：图引导的 RCA agent（Graph Traversal Agent）——LLM 推理 + 确定性图/工具操作在"类型化证据图"上遍历取证，并把运维约束（只读取证、传播感知、有界搜索、独立校验）显式编码进状态机；难得的是它**主动区分"prompt 调出来的涨点"与"去掉场景提示后仍存活的涨点"**。
- **解决什么问题 / 为什么重要**：是方向 B 里少见的"诚实评估"范本——这类 LLM-agent RCA 极易因 benchmark 捷径而虚高，本文用 prompt 消融、telemetry 无泄漏测试等把每条结论标为 supported/pending/out-of-scope。对你警惕"agent 系统涨点是否来自证据而非捷径"很有方法论价值（这也是你 C 方向偏好的"机制/可信度"视角，只是落点在运维应用，故归 B）。
- **核心方法**：把运维约束映射到类型化事件图 + LangGraph 遍历状态机 + 独立校验阶段；LLM 在证据图上推理，确定性图/工具操作负责取证、限定搜索边界、校验候选判定。
- **主要结果**：在 ITBench 快照、固定 qwen-plus 评审下，根因实体 F1 由前代 0.6087 提升至 0.9130（23 场景子集）；但**作者主动揭示**：去掉场景特定提示后仅剩 0.6958 F1（19 场景子集），且存活增益集中在"真因即证据图中已有注入故障对象"的 ChaosMesh 场景，故标注为 benchmark-coupled 而非通用跨集群 RCA 证据；live-cluster 仅作压力测试，不做生产就绪/MTTR 声明。
- **值得追问 / 局限**：① 去 prompt 提示后 0.70 F1、且增益 benchmark 耦合——真实跨集群泛化能力其实未被证明，这点作者已坦承；② 评测局限在 ITBench OpenTelemetry-demo 快照，真实告警/trace 不稳定导致无法受控评分，落地差距仍大。
