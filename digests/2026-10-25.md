## A. 核心方法（ROM 嵌入式 GNN 做抗震数字孪生 / 连续时间图生成模型的稳定性保证，取 2 篇）

### 1. Topology-Adaptive Seismic Response Prediction of Interconnected Structural Systems Using Reduced Order Model Embedded Graph Neural Network
- 链接：https://arxiv.org/abs/2610.28378
- 作者：Huangbin Liang, Beatriz Moya, Francisco Chinesta, Eleni Chatzi（4 位；eess.SP）
- **TL;DR**：电站设备通过母线/软导线互连，部件响应同时受本地结构属性、机械耦合、系统拓扑与瞬态激励影响；高保真有限元太慢、纯数据驱动难泛化。本文提出 **ROMeGNN**：把每个部件先降阶成模态表示、作为一个**可微的动力学算子**嵌进 GNN，让图消息传递只去学"拓扑相关的部件间相互作用力"，而非直接回归整段响应。
- **解决什么问题 / 为什么重要**：命中 A 的**时空图 / 拓扑自适应**主线，同时带**内生可解释（横切重点）** 色彩——它不是黑盒拟合，而是"已知部件级物理（ROM 求解器）+ 数据驱动的跨拓扑耦合力"的混合结构，因而能在**布局、部件组合、激励场景变化**时免重训迁移。这套"把可微物理算子塞进图节点、只用 GNN 学耦合"的范式，对任何在可变拓扑的互连系统上做实时预测的时空图建模都有方法迁移价值。
- **核心方法**：① 系统建成图——结构部件为节点、机械互连为边；② 每个高保真部件模型降阶为模态表示，构成 GNN 内的**可微 ROM 求解器**；③ GNN 不直接出响应，而是估计**拓扑相关的相互作用力**，作为耦合输入喂进 ROM 求解器推进模态状态；④ 已知部件物理被保留，数据驱动的消息传递只负责复杂的部件间力。
- **主要结果**：在受随机地震输入的互连电站设备上验证，能快速给出与抗震损伤评估相关的响应量，并在不同布局 / 部件组合 / 激励场景下保持适用；相比纯数据驱动模型，强调了"物理嵌入 + 图学习"在实时、可解释、拓扑自适应数字孪生上的潜力。
- **值得追问 / 局限**：① 验证限于电站互连设备这一类工程系统与模拟地震输入，对真实地震记录、更大规模或拓扑随时间重构的网络能否同样免重训迁移，摘要只给定性结论，需正文的误差与外推实验坐实；② "GNN 只学耦合力、物理交给 ROM"的分工在部件本身非线性很强（超出模态线性假设）时精度如何退化，是这套混合架构的天然边界。

### 2. Stabilizing Filters for Graph Signal Generation
- 链接：https://arxiv.org/abs/2610.28318
- 作者：Martin Schmidt, Gonzalo Mateos（2 位；eess.SP，交叉 cs.LG / stat.ML）
- **TL;DR**：把底层图并入生成模型能做"结构感知"的图信号分布建模，但图常常是带噪或估计不准的，结构误差会污染生成过程。本文研究一类**连续时间生成模型**（其动力学把**图滤波器**与一个**学到的图神经网络**结合，即拓扑 Schrödinger 桥里用的"图感知参考动力学"，是 graph neural ODE 的近亲）在图扰动下的**结构稳定性**，推出 **Wasserstein 稳定性界**并据此给出有稳定性保证的滤波器设计。
- **解决什么问题 / 为什么重要**：命中 A 的 **continuous-time / 图 ODE** 方法线。已有工作只给了 graph neural ODE 的稳定性保证，而"图滤波器 + 学到的 GNN"这类参考动力学的鲁棒性此前基本空白。本文把"图估计有多准"和"生成分布会偏多少"用一个可量化的 Wasserstein 界连起来，并进一步落到**可显式写出、带可证稳定性的多项式滤波器族**——对所有把不完美图结构喂进连续时间生成模型的工作，这是"该信多少、怎么设计滤波器"的理论工具。
- **核心方法**：① 针对"图滤波器 + 学到的 GNN"组合动力学的连续时间生成模型，推导量化图扰动→生成信号分布偏移的 **Wasserstein 稳定性界**；② 以该分析为指导，提出在**结构稳定性**与**诱导信号平滑**之间权衡的滤波器设计框架；③ 刻画最优滤波器设计，并给出一族**有可证稳定性保证的多项式滤波器**。
- **主要结果**：在合成图与**真实 fMRI 信号**上的实验支持理论——所提滤波器在保持生成性能的同时显著增强了结构稳定性（对图扰动更不敏感）。
- **值得追问 / 局限**：① 稳定性保证针对多项式图滤波器这一特定族，对更一般/更深的学习型图动力学是否仍可推广，需看正文假设；② "稳定性 vs 信号平滑"是显式权衡——过度追稳可能过平滑掉有用的高频结构信息，实际该如何在具体任务上定这个平衡点，摘要未给操作性准则。

## B. 应用场景（首个公开云事件根因/缓解基准 CloudIR-Bench / 可重构数据中心网络的动态探测故障定位，取 2 篇）

### 3. CloudIR-Bench: A Benchmark for Root Cause Analysis and Mitigation of Cloud Incidents
- 链接：https://arxiv.org/abs/2610.29185
- 作者：Hoang Tran, Huong Ha, Tri Dang, Jeffrey Chan, Hongyu Zhang（5 位；cs.SE）
- **TL;DR**：根因分析（RCA）与缓解动作预测是事件管理的核心，近期用 LLM 从事件报告文本里预测根因/缓解已有不错结果，但进一步进展受困于**没有公开数据集**——现有工作都靠私有数据，透明性、可复现性、泛化都受限。本文放出 **CloudIR-Bench**：据称是**首个公开**的、面向"基于事件报告的 RCA + 缓解预测"的数据集 + 评测框架。
- **解决什么问题 / 为什么重要**：正中 B 的**监控告警 + 根因定位（AIOps）** 主线，且解决该领域长期痛点——缺可共享、可复现的真值基准。数据从**五大云系统**的真实事件报告整理而来，覆盖真实生产故障与工程师推理；同时开源含 **8 个近期 LLM 方法**的评测框架，做了 zero-shot 与 in-context learning 实验及"LLM 在哪里、为何失败"的定性分析。对做 AIOps/RCA 方法评测的人是现成的公开试验台（代码已开源）。
- **核心方法**：① 从五个主流云系统的事件报告中整理数据集，保留真实故障场景与工程师的推理过程；② 开源评测框架集成 8 个近期基于 LLM 的 RCA/缓解方法；③ 评测含 zero-shot 与 in-context learning 两种设定，并辅以定性分析定位 LLM 失败的"在哪/为何"。
- **主要结果**：综合评测揭示了现有 LLM 在该任务上的能力与局限（摘要层面给的是"能力边界被系统刻画"这一结论，具体数值见正文/仓库）；定性分析指出了 LLM 在根因/缓解预测上典型的失败模式。
- **值得追问 / 局限**：① 数据源于"事件报告文本"，即已被人工整理过的事后叙述，与**在线、带噪的原始遥测/告警流**差距明显——它评的是"从报告里读出根因"，不一定等价于"从监控信号里定位根因"，外部效度需据此理解；② "首个公开"的代价是报告级别而非 per-signal 真值，适合评 LLM 文本推理、但不直接支撑时序/图类 RCA 方法的端到端评测。

### 4. D-Pingmesh: Dynamic Probing and Fault Localization for Reconfigurable Datacenter Networks
- 链接：https://arxiv.org/abs/2610.29787
- 作者：Yunze Wei, Kaicheng Yang, Xiaohui Xie, Dunkai Mao, Peiying Tao, Yikai Zhao（12 位；cs.NI）
- **TL;DR**：Pingmesh 靠服务器间周期 ping 监控数据中心网络，但在**可重构网络**里拓扑工程（TPE）与流量工程（TE）让"统一服务器对探测"变得低效——pinglist 既浪费预算重测公共路径、又漏掉低概率接口，且控制面频繁更新要求 pinglist 快速刷新、还在控制面边界带来路径歧义。本文提出 **D-Pingmesh**：与 TPE/TE 控制面**协同设计**的探测 + 故障定位系统。
- **解决什么问题 / 为什么重要**：命中 B 的**故障定位 / AIOps**应用，与 CloudIR-Bench 互补——一个是"从事件报告文本做 RCA"，一个是"从主动探测做网络层故障定位"。它针对可重构数据中心这一现实难点（拓扑在动、探测预算有限、控制面边界有歧义），把"该探哪些路径"和"怎么从探测结果反推故障"都做成控制面感知的在线算法。
- **核心方法**：① **控制面感知的生成器**：在当前 TPE/TE 快照下贪心接纳"接口覆盖率高"的探针，构建任务高效的 pinglist；② **增量 replay-and-repair**：重构发生时增量更新 pinglist 而非从头重算；③ 在控制面边界用 **Rho-EM 定位器**，以 EM 式迭代联合推断每任务的"旧/新路径混合权重"与故障集。
- **主要结果**：在 8-pod 可重构拓扑的动态 TPE/TE 下，达 0.99 覆盖目标时**任务数比 Pingmesh 少 17.7 倍**、每次 pinglist 生成比 RD-Probe **快约 5.1 倍**；ns-3 仿真中边界感知定位把 micro-F1 从 deTector PLL 基线的 **0.871 提到 0.953**；实测台部署展示了**秒级**故障定位且主机开销低。
- **值得追问 / 局限**：① 评测主要在 8-pod 仿真 + 单一测试台上，面向更大规模生产网络、更复杂故障（多点并发/间歇性故障）时定位精度与开销如何，需进一步验证；② Rho-EM 的"旧/新路径混合权重"推断依赖对控制面快照的准确掌握，控制面信息滞后或不一致时，边界歧义能否仍被正确消解，是该方法的现实风险点。

## C. Agent / 机制（安全相关行为探针的"读/写分离"机制分析 / agent 交互偏好记忆基准的祛魅，取 2 篇）

### 5. Probing and Steering for Safety-Relevant Behaviours in Large Language Models
- 链接：https://arxiv.org/abs/2610.30363
- 作者：Nimun Bajwa, Massimo Poesio（2 位；cs.LG，交叉 cs.AI / cs.CL / cs.CY）
- **TL;DR**：激活探针是在 LLM **残差流**里算出的方向，既用来"检测"安全相关行为、又能把方向加回流里来"引导（steer）"这些行为。本文在**一个模型、一条流水线**上系统交叉主要设计选择，跨三种行为（欺骗、高风险情境意识、谄媚）同时评估每个方向当"检测器"和当"引导向量"的效果，检验此前文献读出来的"读/写分离"假说。
- **解决什么问题 / 为什么重要**：命中 C 的**机制/现象分析 + 表征几何（residual stream）** 优先类，是一篇你偏好的"祛魅/把假说做扎实"工作。它要回答的是可解释性安全工具里一个关键问题——**同一条方向，既能最好地"检测"行为、又能最好地"引导"行为吗？** 结论是"看行为、看数据"，并非普适规律，这对任何想用单一激活方向既做监测又做干预的安全方案都是重要修正。
- **核心方法**：① 固定一个模型（Llama-3.1-8B-Instruct）、一条流水线；② 交叉两种估计器（差值均值 difference-of-means 与逻辑回归）× 三种 token 池化（last / mean / 学习注意力）；③ 为检测或引导分别选合适层；④ 每条方向都评两次——当行为检测器、当把输出推向该行为的引导向量。
- **主要结果**：此前文献合起来暗示一种**读/写分离**——逻辑回归方向"读（检测）"最好、差值均值方向"写（引导）"最好；本文发现该分离在**欺骗、高风险**上成立，但在**谄媚**上反转，且反转部分源于**数据而非估计器**；最佳池化与层的选择依行为与数据而变，**最会引导的层可能远在最会检测的层之前**；"改变模型感知"与"诱发行为"两种引导度量该用哪个也依任务而定，两者有时直接冲突。
- **值得追问 / 局限**：① 结论基于单一 8B 模型 + 三种行为，是否推广到更大模型、更多安全行为（如拒绝、越狱倾向）未验证；② "读/写分离会翻转、且受数据影响"说明这类激活方向工具**缺乏跨行为的稳定规律**，意味着每个新行为都得重新做这套交叉选择，工程上并不便宜——如何得到更可迁移的方向是开放问题。

### 6. Why Bother Me Again? Benchmarking Personal Agent Memory for Interaction Preferences (MemPABench)
- 链接：https://arxiv.org/abs/2610.30485
- 作者：Jialin Li, Zhenhao Chen, Hanjun Luo, Hanan Salam（4 位；cs.AI，交叉 cs.CL）
- **TL;DR**：个人智能体在承担越来越复杂的日常任务，但重复提问、无谓确认、不请自来的打扰会把"能干的助理"变成"交互负担"；减负要求 agent 记住**用户想怎样被协助**。但现有记忆基准多测事实召回与个性化回答，很少测 agent 能否学到并据之行动的**交互偏好**。本文提出 **MemPABench**：一个**on-policy** 评测个人 agent 记忆的交互环境。
- **解决什么问题 / 为什么重要**：命中 C 的 **memory（优先类）**，且是一篇"现象分析/祛魅"——它把 agent memory 的评测从"记住事实"推进到"记住并执行交互偏好（何时澄清、何时确认、何时自主行动）"，并给出一个对主流记忆系统并不友好的结论。对研究 agent memory 机制的人，它既是新基准、也是"当前记忆到底行不行"的一次冷静体检。
- **核心方法**：① 长程任务要求 agent 自己决定**何时澄清、确认或自主行动**；② 4 个有据可循的模拟用户、横跨工作与个人情境持有 14 条偏好；③ 反馈覆盖四个月 99 个会话，每个用户 5 次事件驱动的偏好变更，测记忆更新；④ 评偏好选择、实际交付行为、以及对情境与偏好变化的敏感性；⑤ 在 4 个 LLM 底座上评 4 种记忆系统。
- **主要结果**：当前记忆对**偏好选择**提升有限——基于检索的系统（Mem0、MemOS、简单 RAG）**不优于"无记忆"**；基于文件的记忆能提升准确率，但会把偏好**错用到不相关情境**；分析显示当前记忆难以检索交互偏好、也难适应偏好变化；**即便正确偏好可得，覆盖 agent 默认交互习惯仍很难**。
- **值得追问 / 局限**：① 用户与偏好是模拟/有据构造的 4 人 14 条，规模与真实人群的多样性差距大，"记忆没用"的结论在更丰富真实偏好下是否依旧，需扩验；② 它诊断出"检索不到 + 改不动默认习惯"两道坎，但未给出解法——是记忆表示、检索机制还是决策策略的问题，留给后续拆解。
