## A. 核心方法（动态有向网络的辫子特征 / GNN 引导交通路由，取 2 篇）

### 1. Spectral Braids: A Topological Descriptor for Dynamic Directed Networks
- 链接：https://arxiv.org/abs/2610.37580
- 作者：Mehmet Emin Aktas, Esra Akbas（2 位；cs.SI，兼 cs.LG）
- **TL;DR**：图机器学习里特征值（谱）通常被当成"一张静态的数字清单"用；但当图随时间演化、且矩阵非对称（有向）时，复特征值会在复平面里**互相缠绕**，这个缠绕的模式正是拓扑学里的经典对象——**辫子（braid）**。本文提出 **spectral braids**：把动态有向网络每一快照聚合成社区级转移矩阵，追踪其复特征值随时间的轨迹，把缠绕读成一个"词"，再经 **Burau 表示**映成定长特征向量喂给任意分类器。
- **解决什么问题 / 为什么重要**：直击 A 的**时序图 / 动态图表征**，而且走的是一条和主流"动态 GNN 做消息传递"很不一样的路线——**不学参数、直接从谱的时间演化里读拓扑不变量**。对关注 temporal graph 的你，它最有价值的一点是**内生可解释**：每个特征值描述"一组社区如何运动"，每次交叉记录"一组社区反超另一组"，特征本身带语义，而不是黑箱嵌入。这正落在 A 的"动态图 + 自解释几何"交叉点上。
- **核心方法**：① 把每个时间快照聚合为**社区级转移矩阵**；② 追踪其**复特征值轨迹**、把缠绕序列读成一个辫子词；③ 用 **Burau 表示**把辫子词映成固定维度特征向量，交给下游分类器；④ 特征语义明确（每个特征值=一组社区的行为，每次交叉=一次反超）。
- **主要结果**：在动态网络分类任务上（标签描述网络在相同起止状态间如何演化的合成在线社区网络），辫子特征达 **97.1% 四分类准确率**，而不追踪特征值的最优特征集仅 **44.5%**；Burau 特征相对朴素谱特征也有明显增益（摘要被截断，未给完整对照数值）。
- **值得追问 / 局限**：① 评测只在**合成在线社区网络**上做，真实动态图（节点/社区数漂移、快照采样不规则、噪声大）里"社区级聚合 + 特征值追踪"是否仍稳、辫子词是否仍可靠配对，是落地前最该压测的；② 方法先验地依赖"先把网络聚合到社区级"，社区划分本身的选择与误差如何传入辫子特征、对划分敏感度多大，摘要未给。

### 2. GNN-Guided Network Reduction for Centralized Urban Traffic Routing
- 链接：https://arxiv.org/abs/2610.36981
- 作者：Nikolai Antonov, Lukáš Chrpa, Andrii Nyporko, Jan Hůla（4 位；cs.LG）
- **TL;DR**：集中式交通路由（CTR）由中央调度器给 OD（起点-终点）车流分配路线、最小化拥堵相关的路段成本，可建成混合整数线性规划（MILP），但在整张路网上求解在"运营时间预算内"算不动；本文让一个 **GNN 先给每条 OD 流对各路段打分**，把高分路段拼进完整 OD 路线、只在**缩减后的路网**上解原始的段-流 MILP——GNN 负责"砍图"、求解器负责可行性与最终路由。
- **解决什么问题 / 为什么重要**：命中 A 的**时空图 GNN + 道路网络**，并示范了一种"学习 + 组合优化"的分工：此前的 Bounded/Smart Routes 用预计算的缩减网络提速，但**不看每条 OD 流里的车辆信息**；本文把车流信息喂进 GNN 来做**流感知的、针对性的网络缩减**，而不是一刀切。对关注"图结构 + 运营级时间约束"的你，这是把 GNN 当"MILP 的智能预处理器"的清晰案例。
- **核心方法**：① 一个专用 GNN 读路网结构 + 车辆-流信息，为**每条 OD 流**给路段打分；② 高分路段并入完整 OD 路线、构成缩减路网；③ 在缩减路网上求解原始的**段-流 MILP**，由求解器保证可行并确定最终路由。
- **主要结果**：在 **Prague-Dejvice、London、New York、Sydney 四个真实城市网络**、两种交通强度下，相对"30 秒全图参考解"的相对目标差，**本方法在每座城市都最小**；跨城市平均而言，这个差距比最佳基线**低 6 倍以上**。
- **值得追问 / 局限**：① "30 秒全图参考"是性能上界的代理，GNN 缩减带来的加速到底换来多少最优性损失、在更大/更拥堵的网络上这个 6 倍优势是否保持，需看绝对运行时与最优 gap 的完整曲线；② 集中式路由假设中央调度器能指派所有车辆路线，现实中部分车辆不受控（混合自主度）时，流感知缩减是否仍成立，是从仿真到部署的关键一跳。

## B. 应用场景（微服务根因分析实证 / 飞机预测性维护时序基准，取 2 篇）

### 3. Free to Look, Free to Reason: Simple LLM Harnesses Outdiagnose Hand-Crafted Root Cause Analysis Agents
- 链接：https://arxiv.org/abs/2610.35767
- 作者：Tingzhu Bi, Xun Zhang, Jinglin Li, Ping Wang, Meng Ma（5 位；cs.AI，兼 cs.DC / cs.SE）
- **TL;DR**：微服务故障的根因分析（RCA）吸引了大量 LLM agent，但它们几乎都是**手工编排**的——标准操作流程、固定阶段、角色化子 agent，各自在自家数据上比少数基线，没人验证"这套编排到底比让一个强模型自己放手调查更强"。本文在 **RCAtlas（8 个公开数据集、90 个经核验案例）** 上，用 **6 个模型 × 3 档推理强度**，把三个"几乎不规定模型怎么调用"的极简 harness（单次证据包调用、SQL agent、Codex 编码 agent）和 5 个已发表 LLM RCA agent、以及统计/因果方法正面对比。
- **解决什么问题 / 为什么重要**：正中 B 的 **root cause analysis / AIOps（监控告警）**，同时是一篇**机制/科学问题**式的 agent 实证（命中 C 的"agent 机制分析"优先类，而非 prompt 技巧）。核心反直觉结论：**越少编排越强**——极简 harness 把更多调查自由度留给模型，反而系统性超过被精心编排、调用被硬编码的 RCA agent。对做监控/AIOps 的你，这是一记重要的方法论校准：别急着给 RCA agent 套 SOP 和角色分工，先量一量"裸模型自由调查"这条强基线。
- **核心方法**：① 构建 **RCAtlas**（8 公开数据集、90 验证案例）作统一评测床；② 对比三类极简 harness（单次证据包 / SQL agent / Codex 编码 agent）vs 5 个已发表 LLM RCA agent vs 统计与因果方法；③ 跨 6 模型 × 3 推理强度扫描，并做案例分析看硬编码的"固定调用"如何跳过决定性证据。
- **主要结果**：极简 harness 最准（三款中档模型上 **PR@1 65–77%**），显著高于已发表 agent（**16–53%**）与非 LLM 方法（**6–39%**），在"两族都跑过"的每个模型上都领先；已发表 agent 把 **1/10 到全部**的模型调用写死在程序里，案例显示这些规定会跳过决定性证据。进一步：**更强模型主要提升可靠性，多轮 harness 主要提升能力上限，更多推理强度最多改几分准确率却把耗时拉长至多 7 倍**；在"比最佳非 LLM 方法更准"的运行里，所有在成本或时间上 Pareto 最优的运行都用极简 harness。
- **值得追问 / 局限**：① PR@1 65–77% 听着高，但 RCAtlas 是 90 个**经核验**案例，真实生产里噪声告警、多故障并发、证据不全时，"自由调查"是否仍压过编排、会不会反而因缺护栏而乱跑，需在线上评测；② 结论"编排有害"更可能是**当前 agent 的编排方式**有害（把调用写死、跳过证据），而非编排本身无用——如何设计"既给自由又给结构"的 harness，是本文留下的开放题。

### 4. Pneuma: A Large-Scale Real-World Time Series Benchmark for Commercial Aircraft Predictive Maintenance
- 链接：https://arxiv.org/abs/2610.37563
- 作者：Jiafeng Lin, Yutian Zhang, Huan Zhang, Yuxuan Wang, Jinyan Feng, Yuhui Liu 等（8 位；cs.LG）
- **TL;DR**：预测性维护对商用航空至关重要，但进展受困于缺乏公开、大规模、真实世界数据集，多数方法只在私有数据上开发评测、可复现性差；本文发布 **Pneuma**——首个基于在役商用飞机机载时序的大规模预测性维护公开基准，围绕引气系统（bleed air）构建，含 **9.2 亿+ 多元时间步、4 种机型、9 个核验过的故障场景**，标签直接对齐真实维护日志。
- **解决什么问题 / 为什么重要**：命中 B 的**时序异常检测（监控告警方向）**，并补上这个领域长期缺的"真实、大规模、可复现"评测床。它把问题结构成三任务——**多元预测、有监督故障分类、无监督异常检测**，并带有真实世界的硬骨头：严重类别不平衡、细微的故障演化、跨机型配置的大方差。对做时序异常/监控的你，这是一个可以直接拿来横评自己方法、且标签来自真实维护记录（而非合成注入）的罕见资源。
- **核心方法**：① 从在役商用飞机引气系统采集 **9.2 亿+ 多元时间步**、4 机型、9 验证故障场景，标签取自真实维护日志；② 结构成多元预测 / 有监督故障分类 / 无监督异常检测三任务、9 个精选子集；③ 统一设置下评测 **4 大方法族、25+ 模型**。
- **主要结果**：即便当代强模型也**难以捕捉细微的故障特征**；进一步分析显示**增加 in-context 示例与多元推断能带来一致增益**，且**预测质量与异常检测性能强相关**（摘要在此处被截断）。作者据此论证 Pneuma 能暴露现有方法在真实故障演化下的短板。
- **值得追问 / 局限**：① "预测质量 ↔ 异常检测性能强相关"是个有用观察，但它是相关性，是否意味着"把预测做好就能顺带做好异常检测"需因果验证；② 基准聚焦单一子系统（引气系统）+ 4 机型，跨子系统/跨机队的泛化、以及真实部署中标签延迟（维护日志滞后于故障发生）如何影响评测公平性，是使用该基准时要留意的。

## C. Agent / 机制（剪枝的电路级机制失效 / 预训练是否在稳定性边缘，取 2 篇）

### 5. Mechanistic Failure Modes of Weight Pruning in Transformer Language Models
- 链接：https://arxiv.org/abs/2610.37126
- 作者：Nabeelah Faumi, Deshan Sumanathilaka（2 位；cs.LG，兼 cs.CL）
- **TL;DR**：剪枝后的语言模型几乎只用准确率和困惑度评判，这默认了"输出行为保住=内部计算保住"；本文用一项在 GPT-2 上的**析因剪枝研究**（幅值 vs 随机 × 注意力头 vs MLP 神经元 × 3 档稀疏度）直接检验这个假设，并以完全刻画过的 **IOI（间接宾语识别）电路**为"真值"、用 activation patching / path patching / direct logit attribution 测量电路完整性。
- **解决什么问题 / 为什么重要**：命中 C 的**机制可解释性 / 电路分析（优先类）**，而且踩在一个实用痛点上——**模型压缩的机制安全性**。核心发现极具警示：存在两种**定性不同的失效模式**，且输出指标与结构检查**都可能看不见**真正的机制损伤。对研究机制/现象、又关心压缩的你，这给出一个清晰主张：评测压缩模型应把**电路级因果分析**作为准确率/困惑度之外的互补维度。
- **核心方法**：① 在 GPT-2 上做析因剪枝：两种重要性准则（幅值、随机）× 两种组件（注意力头、MLP 神经元）× 三档稀疏度（3%、50%、70%）；② 以 IOI 电路为真值、用 activation patching、path patching、direct logit attribution 测电路完整性；③ 在 **Greater-Than 电路**上复现，看关键组件类型是否随电路架构而变。
- **主要结果**：**幅值头剪枝 ≥ 直接"清零"电路**——面向输出的头被移除、模型掉到近乎随机；**幅值神经元剪枝（30%）却把电路"反转"**——全部 26 个电路头都完好，但 Name Mover 贡献**翻符号**、模型系统性地偏好错误的名字（准确率 17.7%），而困惑度却把它排得**比随机头剪枝更"没坏"**（74.6 vs 140.1）；Greater-Than 电路的复现表明"关键组件类型取决于电路架构"。结论：输出指标与结构检查都可能漏掉机制损伤，需电路级因果分析作互补。
- **值得追问 / 局限**：① 结论基于 **GPT-2 + IOI/Greater-Than** 两个受控电路，更大模型、更复杂/未被完全刻画的任务上"困惑度漏判机制损伤"是否同样严重、"符号翻转"是否普遍，是最该推广验证的；② 作为诊断主张它很有力，但"该用哪种电路级指标、代价多大、能否规模化到生产压缩流水线"仍是开放工程问题。

### 6. Does LLM Pre-Training Typically Occur at the Edge of Stability?
- 链接：https://arxiv.org/abs/2610.36778
- 作者：Yuhang Cai, Haodong Wen, Haofeng Huang, Deyi Liu, Yiyuan Ma, Kaifeng Lyu（6 位；cs.LG）
- **TL;DR**：二次近似是研究神经网络优化的常用透镜，但近期证据对其预测力提出质疑；本文重审二次近似作为"训练动态模型"的保真度、聚焦它在 **LLM 训练**里的失效模式，先指出一个与学习率无关的失效——**凸性边缘（Edge of Convexity, EoC）**：持续的负曲率让二次动力学无论学习率多小都发散，而真实动力学仍稳定；在剔除这个 LR 无关的不稳定后，再给出**自适应优化器下随机训练的 EoS 广义定义**。
- **解决什么问题 / 为什么重要**：命中 C 的**训练动态（优先类）**，直指一个被广泛引用却未在 LLM 场景严格检验的概念——Edge of Stability。它的贡献是**概念澄清 + 实证**：把"二次近似发散"拆成"LR 无关的负曲率发散（EoC，是近似本身的病，不是真训练的性质）"与"真正的 EoS"，并用一个"抬高 LR 会让二次动力学显著发散、却几乎不改真实动力学"的可操作判据来定义后者。对研究训练动态/优化几何的你，这是把一个模糊概念落到可测量判据上的扎实工作。
- **核心方法**：① 识别并命名 **EoC**——持续负曲率导致二次动力学与 LR 无关地发散、而真实动力学仍稳；② 剔除 EoC 影响后，提出面向**自适应优化器 + 随机训练**的 EoS 广义定义（以"增大 LR 是否让二次动力学显著发散、而真实动力学基本不变"为判据）；③ 在不同规模（至多 787M）的多个 LLM 预训练运行上实测。
- **主要结果**：在至多 **787M** 参数的多个 LLM 预训练运行中发现：**(1) EoC 在所有 LLM 预训练里都出现**；**(2) EoS 也普遍但并非普适**——在某些设置下会消失（摘要在此处被截断，未给消失的具体条件）。作者据此主张：用二次近似理解 LLM 训练动态时，必须先把 EoC 这种"近似自身的病态"分离出去，否则会误判真实的稳定性行为。
- **值得追问 / 局限**：① 最大规模 787M 相对前沿 LLM（十亿到千亿级）仍偏小，EoC 普遍 / EoS 非普适的结论在更大模型、更长训练、不同数据配比下是否保持，是外推性的关键；② "EoS 在某些设置下消失"的边界条件是本文最该展开的点（摘要截断处），它直接决定这套诊断能否指导实际的学习率/优化器选择。
