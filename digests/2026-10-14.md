## A. 核心方法（图上的缺失/不规则信号，取 2 篇）

### 1. When Missingness Follows the Graph: Beyond Feature Propagation for Missing Features
- 链接：https://arxiv.org/abs/2610.18113
- 作者：Enrico Chialà, Francesco Ferrini, Antonio Longa, Bruno Lepri, Filippo Maria Bianchi, Manfred Jaeger（7 位；cs.LG / cs.AI）
- **TL;DR**：GNN 通常假设节点特征完整，现有处理缺失特征的图方法靠"沿边传播已观测值"，但这些方法几乎只在"特征按节点独立、均匀随机缺失"下评估；本文指出真实场景（如传感器网络的局部感知失效）里**缺失本身沿图结构成片发生**，形式化为「图结构化掩码依赖」，并提出 **PEMix**——不传播观测值，而用全局结构表征条件化一个不完整特征的概率模型，再做消息传递。
- **解决什么问题 / 为什么重要**：正中 A 的**图 + 不规则/缺失数据**，且戳中一个被长期忽视的评估盲点：把缺失当成 i.i.d. 均匀随机，掩盖了真实传感器网络"一片节点同时掉线"的相关性缺失。论文先在理论与实验上说明传播类方法在这种相关缺失下效果大变，再给出对成片缺失更鲁棒的建模路线——这对把 GNN 用在真实传感、监控、缺失插补场景很有现实意义。
- **核心方法**：形式化"图结构化掩码依赖"（缺失指示的联合分布由图塑造）并给出可控生成机制 → 对传播类方法在该设定下做理论与实验分析 → PEMix：用全局结构表征条件化不完整节点特征的概率模型，在消息传递之前完成，而非传播观测值。
- **主要结果**：在受控的图结构化缺失与自然发生的缺失下，PEMix 都保持鲁棒，**在缺失变得严重时优势尤为明显**；而传播类方法的效果相对"均匀随机缺失"基准发生显著变化（即原有评估高估了它们）。
- **值得追问 / 局限**：① 用"可控机制"注入的图结构化缺失，与真实传感器网络的掉线/堵塞模式吻合度如何，决定结论外推性；② 方法聚焦静态图上的特征缺失，若缺失同时在**时间维**成片发生（时序掉线段），该框架如何扩展到时空设定未展开。

### 2. PING: Physics-Informed Graph Neural Network for Advection-Diffusion Processes with Applications to Solar Power Forecasting
- 链接：https://arxiv.org/abs/2610.18280
- 作者：Jelena Simeunović, Baptiste Schubnel, Pierre-Jean Alet, Pascal Frossard, Rafael E. Carrillo（5 位；cs.LG / eess.SP）
- **TL;DR**：平流-扩散（如云团运动）既是数值 PDE 的经典对象，又难以直接用在**空间不规则的传感器网络**（气象站）上；本文从图信号处理视角把平流-扩散粒子建成图上的信号，提出 **PING**——把离散化的平流-扩散方程作为**软约束写进损失**，在不规则网格上预测未来粒子浓度，并与光伏发电预测模型耦合。
- **解决什么问题 / 为什么重要**：命中 A 的**时空图信号 + 不规则采样网格 + 结构化/物理归纳偏置**。它不是纯黑箱时空预测，而是把物理守恒（平流-扩散方程）当作先验显式约束学习，既保留图信号方法对不规则空间布点的适应力，又用物理一致性抑制非物理解——是"内生结构约束 + 可学"在时空预报上的又一干净样本，对气象/能源等地理不规则传感任务有直接价值。
- **核心方法**：把平流-扩散粒子建成不规则图上的信号 → GNN 预测未来浓度 → 将离散化平流-扩散 PDE 作为软约束加入损失、引导学习走向物理一致解 → 与光伏发电预测模型耦合，融合地面传感器与含云量信息的卫星图像做日内预测。
- **主要结果**：在合成与真实传输现象数据集（含海表温度、云指数）上与 SOTA 模型**持平**；与光伏功率预测耦合的混合方案通过数据融合提升了**日内光伏发电预测精度**。
- **值得追问 / 局限**：① 与 SOTA "on par"而非超越，物理软约束的净收益主要体现在物理一致性/数据稀缺时的外推而非点精度，需看更极端/稀疏布点下的差距；② 平流-扩散方程对云团等真实湍流过程是简化模型，模型误设下软约束会否反而引入偏差，未充分压力测试。

## B. 应用场景（可解释步态抑郁识别 / 鲁棒异常检测，取 2 篇）

### 3. Contactless Gait-Derived Features as Candidate Digital Biomarkers of Depression Severity in Adolescents
- 链接：https://arxiv.org/abs/2610.18510
- 作者：Shuai Liu, Xiang Li, Guangxin Dai, Mengyuan Yu, Wenkong Wang, Hanchi Liu（11 位；eess.SP）
- **TL;DR**：青少年抑郁严重度评估目前依赖阶段性临床量表，本文构建 **LD3D-ADG**（119 名青少年的深度传感器步态数据集，39 健康/41 轻度/39 中重度），并提出 **UMLPA-GCN**——一个在三个解剖骨架分区上建模**时空步态动态的图卷积网络**，做严重度分层并给出可解释的数字生物标志。
- **解决什么问题 / 为什么重要**：强命中 B 的**行为/神经相关的健康监测**（与脑功能/心理健康时序同族），并横切 A 的**时空图卷积**与自解释。它把骨架关节建成图、在空间（关节分区）与时间（步态周期）两维做 GCN，属于"时空图 + 临床可解释"的应用样本；更关键的是产出的是**可对齐到临床量表的内生生物标志**（手臂摆动、骨盆运动、关节活动范围、摆臂不对称），而非事后黑箱打分——符合"结果导向 + 内生可解释"的取向。
- **核心方法**：深度相机采集非接触 3D 步态 → 按三个解剖骨架分区建图 → UMLPA-GCN 建模时空步态动态 → 参与者独立五折交叉验证分类严重度 → 关联到 17 项汉密尔顿抑郁量表（HAMD-17）抽取数字生物标志。
- **主要结果**：参与者独立五折下分类准确率 **75.63%**、macro-F1 **75.52%**、macro-AUC **0.839**（95% CI 0.779–0.899）；三类召回分别为健康 87.18%、轻度 63.41%、中重度 76.92%；识别出**摆臂减少、骨盆运动变慢、关节活动受限、摆臂不对称**为与更高 HAMD 分相关的主要候选标志。
- **值得追问 / 局限**：① 单中心 119 人、类别样本小，轻度一类召回仅 63% 说明中间档最难分，需外部/前瞻验证；② "生物标志"目前是相关性证据（与量表相关），因果性与对混杂（身高、情绪当下状态、拍摄条件）的稳健性未解决。

### 4. Robust Logical Anomaly Detection under Capture Shifts via Synthetic Anomalies
- 链接：https://arxiv.org/abs/2610.18295
- 作者：Ufuk Efe, Alptekin Temizel（2 位；cs.CV / cs.LG）
- **TL;DR**：逻辑异常检测（缺件、多件、错误组合）通常靠"测试图与正常图的距离"打分，在 MVTec LOCO 等基准上近乎满分，但本文发现它们**对采集条件变化极不鲁棒**——在亮度下降/缩小等异质扰动下，最强的 CSAD、SALAD 从 97.7%/96.4% 跌到 68.1%/62.3%；为此提出一个**不与正常数据比对**、改为用"正常图 + LLM 生成的合成异常"训练分类器的框架。
- **解决什么问题 / 为什么重要**：命中 B 的 **anomaly detection + 分布/采集漂移鲁棒性**。它的两点方法学价值可迁移到监控/告警场景：其一，揭示"干净基准高分"会掩盖对运行时条件漂移的强敏感性（监控系统上线后环境必然漂移，这个教训通用）；其二，用**语言模型从产品简述推导异常类型与编辑指令、图像编辑器合成异常样本**、再让分类器区分"合成异常 vs. 自动发现的正常子模式"——把"异常是什么"显式化为可学判别边界，而非依赖对正常分布的密度估计。
- **核心方法**：异质扰动协议（随机保持原样 / 降亮度 / 缩小）量化鲁棒性 → 从产品简述用 LLM 推导异常类型与编辑指令 → 图像编辑器据此在正常图上生成合成异常 → 分类器学习区分"编辑后异常图"与"自动发现的正常子模式"，打分时不与正常样本比对。
- **主要结果**：干净图上 94.9% AUROC（仅比 SALAD/CSAD 低 1.5–2.8 点），**扰动协议下 94.1%**（远高于基线崩塌后的 60–68%）；即便训练时完全不含亮度/缩小增强，仍达 92.5%（干净 93.2%）——说明鲁棒性来自"学规则违背"而非见过该扰动。
- **值得追问 / 局限**：① 场景为工业视觉逻辑异常，迁移到时序/日志**监控告警**需把"从产品简述生成合成异常"重定义为"从系统规格生成合成故障序列"，可行性待验证；② 合成异常质量依赖 LLM 对异常类型的覆盖，罕见/未知异常类型的召回是软肋。

## C. Agent / 机制分析（高优先级，取 2 篇）

### 5. Depth Memory
- 链接：https://arxiv.org/abs/2610.18809
- 作者：David González-Martínez, Philipp Nazari, T. Konstantin Rusch, Shiwei Liu（4 位；cs.LG）
- **TL;DR**：残差连接以"逐层相加"方式跨网络传播信息，近期的 mHC、AttnRes 等用更强的深度聚合机制提升了语言建模；本文把"跨深度的表征混合"**重新形式化为一个跨层存取信息的记忆问题**，提出统一框架 **Depth Memory（DM）**，并据此派生出用递归最小二乘做跨层检索的 **Linear Depth Memory（LDM）**，沿深度传播残差流、线性联想记忆流、逆协方差流三条流。
- **解决什么问题 / 为什么重要**：强命中 C 的**表征几何 / 残差结构 / 机制理解**。它的看点不在刷点，而在给出一个统一视角：把 PreLN Transformer、mHC、AttnRes 都解释成"把表征当作记忆跨层写入/读取"的不同实例（AttnRes 的记忆流是显式层表征的增长缓存，mHC 是扩展的残差流）。这把"深度方向到底在传递/保留什么信息"这一含糊问题变成可形式化、可设计的对象，对理解 residual stream 的结构与功能有基础价值。
- **核心方法**：把跨深度表征混合形式化为"流（stream）"载体的存取问题 → 统一描述 PreLN / mHC / AttnRes → LDM：用递归最小二乘把"跨深度信息检索"写成回归问题，传播残差流 + 线性联想记忆流 + 逆协方差流 → 给出降低峰值激活内存与内存流量的硬件感知实现。
- **主要结果**：在 **400M 与 1.5B** 参数规模上，LDM 在 PreLN、mHC、AttnRes 基线中**取得最低困惑度**，并保持有竞争力的 zero-shot 准确率；硬件感知实现降低了训练/推理的峰值激活内存与内存流量。
- **值得追问 / 局限**：① "记忆流"视角是否带来可解释性上的实际抓手（比如能否读出某层写入了什么语义），还是主要作为架构设计语言，论文更偏后者；② 最大仅到 1.5B，RLS/逆协方差流在更大规模与更长上下文下的稳定性与算力开销增长曲线待验证。

### 6. Why Agentic Workflows Fail: A Taxonomy Derived from Literature and Empirical Data
- 链接：https://arxiv.org/abs/2610.17418
- 作者：Xin Li, Rami Bahsoon, Tao Chen（3 位；cs.SE / cs.AI）
- **TL;DR**：agent 工作流把 LLM 与规划、记忆、工具、执行环境、迭代反馈拼在一起，故障难诊断——同一个表层症状可能源自模型行为、工作流编排、外部工具、基础设施或它们的交互；本文提出**源头感知（source-aware）的失败分类学**，核心是"**工作流阶段 × agent 能力**"的双轴定位矩阵，把症状追溯到中间过程状态，并用文献与 GitHub 证据做实证对比。
- **解决什么问题 / 为什么重要**：这是今日唯一的 agent 类，且是"优先"的**机制/现象分析 + 根因定位**而非 prompt 技巧。它正面回答"agent 为什么失败、失败发生在哪个环节、是哪种能力出问题"，把 agent 可靠性当作**系统问题**而非单纯模型输出问题——与 B 的**根因分析/故障定位（AIOps）**在方法论上同构：双轴定位矩阵（过程轴×功能轴）本质是把"用户可见症状 → 中间过程状态"的归因结构化。对理解 agent 失败模式、设计评测与故障注入、以及工程 triage 都有参考价值。
- **核心方法**：构建源头归因 + 三个实证维度（具体失败类型词典、工作流阶段定位、agent 能力定位）→ 以"工作流阶段（横轴过程）× agent 能力（纵轴功能）"双轴矩阵定位中间过程状态 → 对文献来源与 GitHub 来源的失败分别做实证分布对比。
- **主要结果**：文献派生的失败集中在**规划、推理、学习、感知、知识**类机制，而 GitHub 派生的失败集中在**执行阶段、执行/动作化、工具、API、基础设施**；最大热点是**迭代执行与动作化（actuation）**；据此主张 agent 可靠性应作为系统问题而非仅模型输出问题来治理。
- **值得追问 / 局限**：① 分类学来自文献 + GitHub 证据，GitHub issue 的采样偏差（愿意上报的多是执行/工具类硬故障）可能放大"执行阶段是热点"的结论；② 提供的是结构化分类与定位框架，尚未给出可自动运行的根因定位工具或量化的 triage 决策流程，离落地的 AIOps 式自动归因还有一段距离。
